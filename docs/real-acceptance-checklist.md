# 真实验收清单 · VM / PMO v2 与可编辑草稿

本清单把 [VM / PMO 接入状态](taskboard-vm-pmo-integration.md) 和 [验收说明](validation.md) 中
“尚未验收”的项目整理为可执行步骤。离线合成媒体联调已通过，本清单只覆盖它不能证明的部分：
真实审批与下载、真实 ASR、PMO 附件追加与读回、阶段写回、NAS 归档、人工试听、画面语义和剪映打开。

每一项都记录 **执行者、日期、版本（包提交 / Taskboard 提交）、证据位置、结论**。
未执行的写“未完成”，不适用的写明原因。证据保存在被忽略的目录（例如 `.local/acceptance-<日期>/`），
不提交素材、凭据或本机路径。

## 0. 需要准备的内容

| 项目 | 提供方 | 说明 |
| --- | --- | --- |
| 指定测试记录 | 用户 | 一条专用于验收的 Base 记录，验收期间不让其他人修改目标附件字段（附件服务无 CAS）。 |
| 真实 VM 源视频 | 用户 | 通过正常 VM 审批队列获取，不手动复制。最好包含：可删的口头禅/重复词、明显的转场或板书变化、至少一处重复出现的词（用于歧义阻断）。 |
| 审核意见文本 | 用户 | 至少两轮：第 1 轮是删词加语音 cue，第 2 轮是定格或范围调整。另准备一条歧义意见和一条多指令意见，用于阻断测试。 |
| ASR 连接 | 用户 / 本机 | 本机包配置中的真实语音服务可用；凭据只在被忽略的本机配置中。 |
| Taskboard 环境 | 用户 | Bridge 已登记、自动执行开关和活动配置已启用、本包已在「新增 Auto-Cut 包」中验证。 |
| 归档目标 | 用户 | 测试专用的 NAS 目录，允许写入，可以构造同名文件。 |
| 剪映 | 用户 | 用于打开草稿的本机，最好另有一台用于异机打开。 |

## 1. 环境与身份预检

- [ ] 包仓库：`git status` 干净，记录 `git rev-parse HEAD`；`pytest -q` 与 `ruff check .` 通过。
- [ ] `python -m auto_cut_slicing doctor` 通过：FFmpeg / FFprobe 可用，Auto-Cut Lite 身份、锁定提交和源码清洁状态匹配。
- [ ] 真实 ASR 冒烟：对一段短真实素材运行 `python -m auto_cut_slicing transcribe <源> --output <words.json>`，
  确认词级时间戳绑定源哈希，且抽查 3 处词界与听感一致。
- [ ] Taskboard 包预览：识别为 `auto-cut-slicing` `0.3.0`、模板 `vm_pmo_review_video` v1、
  contract v2、driver `vm_pmo_review_video_v2`；manifest 摘要与包仓库一致。
- [ ] Taskboard 离线脚本 `check-vm-pmo-offline.mjs` 在当前两个提交上再跑一次，并通过。
- [ ] Bridge 与 Taskboard 只监听 `127.0.0.1`。

## 2. 初稿（`initial`）

- [ ] 在测试记录上通过**真实状态边沿**触发初稿，不使用模拟事件、复制标记或手改数据库。
- [ ] 走正常 VM 审批队列，审批通过后才下载；等待审批期间不占用剪辑槽。
- [ ] 源视频带有采集回执，记录源 SHA-256、字节数和时长。
- [ ] `plan.json`：阶段为 `initial`，`parent: null`，`timeline_basis: vm_original`，原始意见码点保持不变。
- [ ] 成片通过 Taskboard 独立校验：H.264/AAC、1920×1080、25 fps、时长、摘要和完整解码。
- [ ] 附件交付：worker 重读附件字段，保留已有附件，只追加新 token，并读回同一 token。
  在 Base 界面上手动核对附件确实存在且可以播放。
- [ ] 读回成功后才回写“初稿完成”；记录 task / run ID 和最新已交付指针。
- [ ] 按 [实际剪辑交付清单](validation.md#实际剪辑交付清单) 逐项复核这条成片：开头第一帧、接缝、首尾语音和人工试听。

## 3. 审核轮次（`review`）

### 3.1 第 1 轮：删词与语音 cue

- [ ] 通过审核触发选项进入，**不产生新的 VM 审批申请**，也不重新下载原视频。
- [ ] 输入中的 parent 冻结为初稿的 run / artifact / delivery / SHA / 字节数 / 时长，并与本地文件一致。
- [ ] 时间坐标以 parent MP4 为基准（`previous_review_video`），不回退到原始 VM 视频坐标。
- [ ] 包内生成 `alignment.words.json`，绑定 parent SHA 和时长，使用真实 ASR（不是合成夹具）。
- [ ] 删词：唯一精确匹配，`must_keep` 保护词不受影响；成片时长按计划缩短，后续音画同步前移。
- [ ] 语音 cue：起点落在完整词上，围绕标注时间，没有为凑整句带入引入语；有画面锚点时差值不超过 0.5 秒。
- [ ] 人工试听每个删词点与 cue 起点：没有切词、残音或吞字，接缝节奏自然。
- [ ] 附件：新稿追加到附件字段，初稿仍保留；读回成功后回写阶段，并更新最新已交付指针。

### 3.2 第 2 轮：基于第 1 轮成片继续返修

- [ ] parent 指向第 1 轮已读回的交付，而不是初稿。
- [ ] 定格 / 范围意见带源哈希绑定的选帧证据；检查所选帧、所有覆盖帧和恢复播放前后的相邻帧，
  确认没有旧内容闪回，原声继续。
- [ ] 附件追加、读回、阶段回写的检查同 3.1。

### 3.3 阻断场景（真实记录上各执行一次）

每个场景都要确认：运行为 `blocked`，原始意见保留在回执中，没有生成计划或 MP4，没有上传或回写“完成”。

- [ ] 歧义：要删除的词在 parent 中出现多次。
- [ ] 多指令：一次手动返修包含多条意见。
- [ ] 保护冲突：删除范围覆盖了 `must_keep` 短语。
- [ ] ASR 不可用：临时停用 ASR 连接后提交语音类意见；恢复连接后重试，确认复用同一 parent、轮次和输出路径，不另分配轮次。

### 3.4 恢复与重试

- [ ] 渲染完成、但阶段回写失败时，单独恢复回写，不重新渲染（成片 SHA 与修改时间保持）。
- [ ] 重启 Taskboard 后重试同一 run，复用相同的 parent、意见、对齐文件和输出路径。

## 4. 最终归档（`finalArchive`）

- [ ] 归档触发选项与编辑触发选项不同；默认关闭，启用后才生效，并且不会补跑历史状态。
- [ ] worker 只读取最新已确认交付指针，重新验证 SHA 后，以不覆盖的方式发布到 NAS 测试目录。
- [ ] 幂等：再次触发归档，同名同 SHA 视为成功，不产生重复文件。
- [ ] 冲突：目标目录预置一个同名但内容不同的文件，Taskboard 显示冲突，不覆盖原文件。
- [ ] 认证 Bridge 请求不携带本机路径。

## 5. 可编辑草稿与剪映打开

- [ ] 用真实素材和真实 ASR 运行 `draft`：完整源视频和分离 WAV 都在草稿素材中，V1/A1 逐段同步，标签保留原文。
- [ ] 在本机剪映中打开：时间轴片段数、时长和删词位置与 receipt 一致，每段可以拖动边界恢复内容。
- [ ] 异机打开（拷贝整个草稿目录）：素材不丢失。
- [ ] 通过后才把 `target_open_verified` 记为 true，并注明剪映版本。

## 6. 性能（可选）

- [ ] 在长素材（例如 30 分钟以上）中叠加多处删词、定格和静音，记录 plan / render 耗时和峰值内存。
  这是 [Taskboard 契约](taskboard-contract.md) 中尚未验收的规模。

## 7. 验收结论记录

完成后在 [validation.md](validation.md) 末尾追加一节“真实验收 · 日期”，分开写明：

- 自动结构 / 解码校验通过的范围；
- 画面内容复核、人工试听、反向 ASR 各自覆盖哪些成片和版本；
- Taskboard 审批、附件读回、阶段回写、归档的真实事件证据（Bridge 事件来源、task / run、附件 token、归档回执）；
- 仍未完成或失败的项及原因。

不得用复制文件、手改数据库、模拟事件或附件顺序代替业务凭据；用户确认也不能代替执行者没有做过的检查。
