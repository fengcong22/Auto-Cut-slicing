# 剪辑经验与交付准则

本文件将实际成片验收中确认的经验用于后续剪辑和返修。每次任务先读本文件，
再按 [任务格式](job-format.md) 或 [Taskboard 契约](taskboard-contract.md) 编制请求，
交付前执行 [实际剪辑交付清单](validation.md#实际剪辑交付清单)。当前用户的明确要求优先。

这里规定编辑判断与交付方式；现有规划器负责执行有证据的范围、词界和效果。
`sentence`、像素变化和完整解码各自提供技术证据，内容是否适合切入、画面是否干净、
节奏是否自然仍须针对素材复核。以下案例时间不能直接套到新素材。

## 已确认规则

| 场景 | 后续任务采用的规则 |
| --- | --- |
| “剪掉某词”，未明确静音 | 精确删除该词的声音和画面，后续时间轴同步前移，总时长缩短。 |
| 明确“剪掉这几个字的声音” | 只静音精确词区间，保留画面与时长。接缝增加停顿是另一种需求。 |
| 标注一个开始时间 | 在附近选择完整词或可独立切入的短语；通常偏移不到约 1 秒，不为 ASR 整句保留前面的引入语。 |
| 指明“首先”“接下来”“空气”等 | 从该完整词的实际发音起点进入，数字只作为定位锚点；使用源绑定 `start_cue`。 |
| 结束时间落在话说到一半的位置 | 补完当前句及必要的自然收尾，避免切断词语，也避免带入下一句。 |
| 开头或接缝残留前一主题 | 取后续已经干净的新内容帧，从切入点覆盖到自然画面能继续的位置，同期原声继续。 |
| “配后面某一秒的画面” | 指定的是选帧位置，不是固定覆盖一秒；替换持续到下一动画或内容可自然恢复的边界。 |
| 前一画面与下一句话衔接太快 | 保持前画面并按语义留出停顿，保留末字衰减，后段画面与声音一起顺延。停顿时长逐处判断。 |
| 多条 PMO 记录有同一 VMID | 复用同一完整源素材，每条记录独立生成成片，不按 VMID 合并或去重输出。 |
| PMO 成片交付 | 名称取“成片命名”，范围取“剪辑保留片段时间”；直接交付 1920×1080、25 fps MP4。 |
| 批次有一条失败 | 记录该条失败原因并继续其他合法输出；外层请求结构无效须先修复。 |
| 用户只返修部分成片 | 保存新版本与变更回执，已验收且未涉及修改的成片保留；完整源媒体始终保留。 |

默认产品仍为可编辑剪映草稿；用户明确选择直接成片或 Taskboard/PMO 成片批次时走 MP4 通道。
同一任务已经确认的交付方式持续有效，无需重复确认或附加生成草稿。

## 首尾语音的判断顺序

1. 保存标注时间、原始指令和本轮补充要求。查看锚点附近真实词级 ASR 与原音频/画面，
   确定本段应从哪个完整词或短语开始；显式切入词优先。
2. `sentence` 会将没有 cue 的句内数字起点退到句首。实际内容只需从中间短语切入时，
   编制结构化 clip 的 `start_cue`，保留终点句界补全，不能直接接受整句回退结果。
3. 约 1 秒是通常的起点误差尺度。超出时审阅内容、确认是否定位正确，不机械夹到一秒以内。
   cue 默认 3 秒搜索半径仅用于找唯一匹配，不代表允许自动多保留 3 秒。
4. 检查终点是否落在词内、句内或不完整语义中。用完整词元和句界证据补到当前句结束；
   起点的约 1 秒提示不限制句末延长。需要保留收尾时，另核查末字衰减和下一词位置。
5. 删词、cue、静音须有绑定当前源 SHA-256 的真实词时间戳与唯一连续完整匹配；
   如有 `must_keep`，另核验保护短语未被删除或静音。匹配歧义时缩小范围或补证据；
   ASR 词元过粗时补更细证据，不能按字数分摊时间。`exact` 的纯范围选取仍可不使用 ASR。

## 两类定格分别处理

**清理切入画面：选后面的新画面。** 检查每条开头和每处拼接的第一帧、前后过渡。
旧图表、旧文字、淡出残影都属于前文残留。选择已确认干净且适合当前语音的新内容帧，
记录源选帧时间与覆盖源区间，覆盖到新动画/内容能自然恢复的位置，原音频继续。
检查全部覆盖帧及恢复播放前后的相邻帧，防止旧画面闪回、重复进场或提前冻结下一动画。
`inspect-freeze` 只提出像素变化候选，不能替代内容判读。

**放缓语义接缝：选前面的收尾画面。** 先定位前句末词、衰减结束、下一条不应保留的词，
以及后段首词。根据语义和原声节奏决定需要留多少停顿；优先保留源中已经存在、
经核验没有下一词的自然尾段，画面用前句的合适末帧定格，后段声音和画面一起顺延。
低能量检测只能辅助判断，须结合真实词级证据与音频复核；不能吞掉末字或把下一词带入来凑时长。

当前 `freeze_frame` 只替换已有区间画面，不插入时间，也不改音频。
增加停顿的现有做法是延长前段以包含可用源尾段，再对该尾段定格；由规划器重算后续目标位置。
渲染前核对计划的实际结束范围：若 ASR 将前句与下一排除词标在同一句，默认 `sentence` 可能继续扩展。
此时对已完成内容与词界复核的该 clip 使用 `boundary_policy: "exact"` 固化保留终点，
起点仍可使用 `start_cue`；保存末词完整、衰减和下一词被排除的证据，不因选择 `exact` 跳过语音复核。
若源尾段不足或下一词已开始，记录此限制并另行处理；不能伪造可用空白、静音掉未经授权的词，
或声称已有独立的“插入静音”接口。句末标点与精确末词终点均不自动保证足够呼吸间隔。

## PMO 映射与版本追溯

- 按记录保存 PMO 记录标识、VMID、原“成片命名”和原“剪辑保留片段时间”。多源批次按源组织请求；
  当前 Taskboard 一份请求一个 source，多个 outputs。表格读取和素材匹配由调用方完成。
- PMO 展示名按原文保留。文件名遇到系统非法字符、保留名或重名时做必要安全转换/消歧，
  另存原名到最终路径的映射；不能仅因源视频相同就少生成一条。
- `source_text` 保留原始码点，包括全角标点、空格和换行。追加反馈、解释、诊断与验收状态
  放入独立的本地变更/验收回执；不要把它们插入不支持的请求字段。
- 回执关联稳定输出/片段 ID、源/ASR/计划/成片哈希、名义与实际范围、cue、选帧和覆盖范围、
  停顿依据及修订前后变化。源坐标和输出坐标分别标明，删词或补停顿后重新计算输出位置。
- 返修使用新输出路径和新请求/回执；`--resume` 只恢复内容相同的原请求，不能用来覆盖旧版。
  原素材、详细时间戳、截图、音频、真实回执和机器路径留在忽略目录，项目文档只保存可复用规则。
- Taskboard 预留输入请求、成片输出、执行结果三项本地交接；宿主是否能同机调用和读取结果须实际联调，
  不能因 CLI 成功就宣称 Taskboard 已接通。

## 已验收案例的可复用含义

| 案例 | 应学到的判断 |
| --- | --- |
| “0:31 剪掉上一章，其他不变” | 删除精确词区间的音画，真实缩短时长；不能默认为静音。 |
| “首先”配后面的 NaOH 画面 | 语音从完整“首先”开始；后续干净帧覆盖到动画恢复，结尾补完正在说的句子。 |
| 物理性质和化学性质 | 即使语音切入正确，也要用新“物理性质”画面覆盖前半段内容残留。 |
| 空气里有什么？ | 标注 0:04，实际从约 4.400 秒的“空气”开始；不能因 ASR 句首在约 2 秒就带入引入语。 |
| 氧气性质很活泼：干净接缝 | 后段总结的第一帧也须检查，提前用干净底板覆盖旧表格残留。 |
| 氧气性质很活泼：自然停顿 | “黑色固体”说完后保留 0.600 秒源尾段并定格前画面，再进入“现在我们可以得出结论”。包含末字衰减与约 0.540 秒低能量间隔，并非 0.600 秒纯静音；不带入源下一词“注意”。 |
| 用性质鉴别两种气体 | 已确认无问题的独立成片，在其他成片返修时保留。 |

上述时间仅说明对应样片中已经确认的处理。以后不固定套用 4.400 秒起点、0.600 秒停顿或某个选帧时间。
用户确认代表对应版本的反馈，不代替新素材的证据，也不自动变成执行者的人工试听记录。

## 以后如何继续沉淀

收到已确认的反馈时，先归纳为“触发条件 → 编辑选择 → 验证方法”，更新本文件；
需要所有任务必读的约束同步到 `AGENTS.md`，执行步骤同步到
`skills/auto-cut-slicing/SKILL.md`，验收项同步到 `docs/validation.md`。
修改技能后运行 `python scripts/install_repo_skills.py` 更新本仓库安装副本。
规则变更提交到 Git；具体媒体结果和用户反馈按版本留在本地回执，保留证据的适用范围。
